# リフティングマスター

子供が毎日のリフティング最高回数を記録し、続けるほどキャラクターのレベルが上がって
進化する Web アプリ。記録はすべて端末の中だけに保存され、外部に送信されない。

設計書: `../docs/superpowers/specs/2026-07-26-lifting-app-design.md`

## つかいかた（開発）

```bash
npm test        # テストを実行（166件）
npm start       # http://localhost:8123/ で開く
npm run icon    # PWAアイコンを作り直す
```

npm install は不要（依存パッケージがゼロのため）。**Node.js 22 以上が必要**。

テストは `node --test test/*.test.js`（glob 展開）で実行する。`node --test test/`
（ディレクトリ指定）は Node 24 では失敗するため使わないこと。

## しくみ

- 記録の正本は `player.records` の配列だけ。レベル・自己ベスト・連続日数は
  そこから毎回計算する（保存しない）ため、表示と実データが食い違わない
- EXP は「その日・そのモードのベストを更新した差分」だけ入る。同じ数字を
  何度入れても増えない
- 計算ロジックは `js/core/` に純粋関数として置き、すべてテストがある。
  画面（`js/views/`）には計算を書かない
- `js/core/player.js` が、その純粋関数群と画面の間をつなぐ層になっている。
  記録の追加・承認・キャラ切り替えなど「プレイヤーの状態を1つ進める」操作は
  すべてここに集約されており、画面側は `js/core/exp.js` や `js/core/evolution.js`
  を直接組み合わせない

## ゲームバランスの調整

数値は `js/core/characters.js` に集めてある。ここを変えるだけで難易度が変わる。

- `MODE_RATE` — ノーバウンド／ワンバウンドの EXP 係数
- 各キャラの `evolutions` — 進化に必要なレベル・回数・連続日数
- 各キャラの `ability` — 特性（倍率のルールは `js/core/abilities.js`）
- `expToNext`（`js/core/exp.js`）— レベルアップに必要な EXP のカーブ
- `GAP_BREAK_DAYS`（`js/svg/chart.js`）— きろく帳の成長グラフで、何日空いたら
  線をつなげずに切るか（既定7日）。毎日はやらない子を想定した見た目の調整値

変更したらテストの期待値も直すこと（`test/exp.test.js` と `test/characters.test.js`）。

## 親の承認について

設定から ON にすると、子供の記録が「承認待ち」に入り、親がパスワードを入れて
確認するまで EXP が入らない。承認画面はパスワードで一度開いても、ホームに戻って
もう一度開くと再びパスワードを聞かれる（開いている間だけ有効な認証で、次に
入り直すときは保持されない）。

**この保護の強さについて:** パスワードはハッシュ化して端末内に保存しているが、
これは「子供が画面操作だけでは突破できない」ことを目的とした割り切りである。
ブラウザの開発者ツールを使える人間は localStorage を直接書き換えられるため、
**本格的な保護ではない**。大人が本気で回避しようとすれば止められない。

パスワードを忘れた場合は、設定時に登録した「あいことば」で解除できる。
両方忘れた場合は、バックアップ JSON を手で編集する以外に方法がない。

## バックアップ

**記録は端末の localStorage にしかない。この端末以外のどこにも複製はなく、
ブラウザのデータを消す・端末を初期化する・別のタブレットに買い替えると記録は
消える。** 設定画面から JSON ファイルとして書き出せるので、ときどき保存して
おくこと。

読み込んだ JSON が壊れていたり検証に失敗した場合は、今のデータは変更せず
エラーだけを出す（詳しくは `js/storage.js` の `load`/`importJson`）。

## 配布

静的ファイルだけなので、GitHub Pages や Netlify にそのまま置ける。
URL を渡せば他の子の端末でも使える（記録は各自の端末に保存される）。

ファイルを変更して配布し直すときは、`sw.js` の `CACHE_NAME` の版を上げること。
上げないと古いキャッシュが配られて変更が反映されない。

## キャラクターについて

9体すべてオリジナル。SVG をコードで生成しているため画像ファイルを持たない。
`tools/preview-characters.html` を開くと27パターン（9体 × 3進化段階）を
一覧できる。
